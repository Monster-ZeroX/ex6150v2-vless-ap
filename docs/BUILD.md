# Building from source

The GitHub Actions workflow (`.github/workflows/release.yml`) does all of this on every `v*` tag. To build locally you need Linux, WSL or macOS for sing-box, and Linux or WSL (x86-64) for the image.

## 1. sing-box

```bash
singbox/build.sh dist/        # -> dist/sing-box, dist/cryptobench
```

Needs Go **1.26.x** and git. `build.sh` does the following:

1. Clones sing-box **v1.14.3**.
2. Copies the exact `sing` and `sing-tun` module versions that release pins, and applies:
   - `patches/sing-pipelined-copy.patch`: bulk copies that are not upgradable to splice use a reader goroutine and a 4-deep buffer FIFO after the first 512 KB, so decrypt and socket writes overlap on two cores.
   - `patches/sing-tun-eexist.patch`: an `EEXIST` when adding the auto_redirect route counts as success. This fixes an intermittent "file exists" startup failure.
3. Replaces `include/registry.go` with a trimmed registry: inbounds tun and redirect; outbounds direct, block and vless; DNS tcp, udp, https and local. The result is about 18 MB instead of 73 MB.
4. Adds `cmd/sbmini`, a minimal CLI with five commands:
   - `run`, `check`, `version`
   - `pin <host> <port> [sni] [ip]`: verify the chain against `host`, print the SPKI SHA-256
   - `resolve <host>`: DoH lookup via 1.1.1.1 / 1.0.0.1
5. Builds with `go build -overlay`. The overlay replaces files in **Go's vendored `golang.org/x/crypto`** (the copy `crypto/tls` uses):
   - `chacha_arm.s` / `chacha_arm.go`: ChaCha20 in ARM assembly (generated by `gen/gen_chacha_arm.py`)
   - `poly26_arm.s` / `poly26_arm.go`: Poly1305 with 26-bit limbs and `UMLAL` (generated by `gen/gen_poly_arm.py`)
   - `poly26_generic.go`, `sum_generic.go`, `chacha_noasm.go`: glue and the pure-Go fallback

   The overlay files are tied to the Go minor version; `build.sh` refuses other versions.

## 2. Test the crypto

`cryptobench verify` compares the assembly with upstream `x/crypto`: 60,000 Poly1305 cases (random and worst-case all-ones inputs, one-shot and streamed in random chunks) and 20,000 ChaCha20 cases (random keys, counters, lengths, buffer offsets, split streams). It exits non-zero on any mismatch. Run it on ARM:

```bash
qemu-arm dist/cryptobench verify      # or copy it to the extender
dist/cryptobench 3                    # throughput per primitive, 3 s each (on the device)
```

**Never ship a build that fails `verify`.** Broken crypto here means silent data corruption or a security hole.

## 3. Firmware image

```bash
LUCI=1 image/build-image.sh 25.12.5 router dist/sing-box out/
```

This downloads and verifies the OpenWrt ImageBuilder for `ipq40xx/generic`, adds `router/` as the files overlay with the sing-box binary, and builds the `netgear_ex6150v2` profile:

| Change | Packages |
|---|---|
| Added | `kmod-tun jq uhttpd zram-swap`, `luci-light` (unless `LUCI=0`) |
| Added (kTLS crypto modules, kept for experiments) | `kmod-tls` and the chacha/poly kmods |
| Removed | `ppp`, `odhcpd-ipv6only`, `odhcp6c`, USB 3 drivers |

Outputs: `*-squashfs-factory.img`, `*-squashfs-sysupgrade.bin` and `sha256-<ver>.txt`.

On WSL, run it with a clean PATH (Windows paths with spaces break ImageBuilder):

```bash
env PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin bash image/build-image.sh …
```

## Full OpenWrt source build (optional)

`tools/build-from-source.sh` builds OpenWrt from source with a custom kernel config. It is needed only for kernel experiments. `tools/999-ipqess-rx-ring-512.patch` is kept as a record of a **rejected** experiment (no gain, unstable). Do not ship it.
